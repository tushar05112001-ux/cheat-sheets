Express.js Cheat Sheet

Express.js is a lightweight web framework for Node.js. It simplifies building web servers, REST APIs, middleware pipelines, and backend applications.

1. Installation and Setup

Definition: Express is installed through npm and used to create HTTP servers and handle incoming requests. 


# Initialize a Node.js project
npm init -y

# Install Express
npm install express

# Install nodemon for development
npm install --save-dev nodemon

Create an app.js file: 


const express = require("express");

const app = express();
const PORT = 3000;

app.get("/", (req, res) => {
    res.send("Hello from Express!");
});

app.listen(PORT, () => {
    console.log(`Server running on port ${PORT}`);
});
  • express(): Creates an Express application.
  • app.get(): Registers a handler for GET requests.
  • res.send(): Sends a response to the client.
  • app.listen(): Starts the HTTP server.

2. CommonJS and ES Modules

Definition: Node.js supports different module systems for importing and exporting reusable code.

CommonJS:


// Import
const express = require("express");

// Export
module.exports = app;

// Import another file
const router = require("./routes/userRoutes");

ES Modules:


// Import
import express from "express";

// Export
export default app;

// Import another file
import userRouter from "./routes/userRoutes.js";

For ES Modules, configure "type": "module" in package.json, or use the appropriate .mjs file extension.

3. HTTP Methods

Definition: HTTP methods describe the action a client wants to perform on a server resource.

  • GET: Retrieves data.
  • POST: Submits data or creates a resource.
  • PUT: Replaces a resource.
  • PATCH: Partially updates a resource.
  • DELETE: Deletes a resource.

app.get("/users", (req, res) => {
    res.send("Get users");
});

app.post("/users", (req, res) => {
    res.send("Create user");
});

app.put("/users/:id", (req, res) => {
    res.send("Replace user");
});

app.patch("/users/:id", (req, res) => {
    res.send("Update user");
});

app.delete("/users/:id", (req, res) => {
    res.send("Delete user");
});

4. Routing

Definition: Routing determines how the server responds to requests based on the requested URL and HTTP method. 


app.get("/", (req, res) => {
    res.send("Home Page");
});

app.get("/about", (req, res) => {
    res.send("About Page");
});

app.get("/contact", (req, res) => {
    res.send("Contact Page");
});

Route handlers receive request and response objects. They can send a response, pass control to another handler, or invoke error handling.

5. Request Object (req)

Definition: The request object contains information about the incoming HTTP request, including parameters, query strings, headers, and body data.

Route Parameters

Route parameters identify specific resources in a URL. 


app.get("/users/:id", (req, res) => {
    const userId = req.params.id;

    res.send(`User ID: ${userId}`);
});

Request: /users/25

Result: User ID: 25

Query Parameters

Query parameters are optional values supplied after a question mark in the URL. 


app.get("/search", (req, res) => {
    const keyword = req.query.keyword;

    res.json({ keyword });
});

Request: /search?keyword=javascript

Request Body

The request body carries data submitted by the client. Use body-parsing middleware to access JSON or form data. 


app.use(express.json());
app.use(express.urlencoded({ extended: true }));

app.post("/users", (req, res) => {
    const user = req.body;

    res.json(user);
});
  • req.params: Route parameters.
  • req.query: Query-string parameters.
  • req.body: Parsed request body.
  • req.headers: Request headers.
  • req.method: HTTP method.
  • req.path: URL path without the query string.

6. Response Object (res)

Definition: The response object provides methods for sending data, setting status codes, and returning HTTP responses to clients. 


res.send("Hello");

res.json({ message: "Success" });

res.status(200).json({ success: true });

res.status(201).json({ message: "Created" });

res.sendStatus(404);
  • res.send(): Sends a response.
  • res.json(): Sends a JSON response.
  • res.status(): Sets the HTTP status code.
  • res.sendStatus(): Sets a status code and sends its standard status message.
  • res.redirect(): Redirects the client to another URL.
  • res.set(): Sets response headers.

A request should normally receive only one final response. Sending multiple responses can cause a "Cannot set headers after they are sent" error.

7. Middleware

Definition: Middleware functions execute during the request-response cycle. They can inspect or modify requests, send responses, or pass control to the next handler. 


app.use((req, res, next) => {
    console.log(req.method, req.url);

    next();
});
  • req: Incoming request object.
  • res: Outgoing response object.
  • next(): Passes control to the next middleware or handler.
  • app.use(): Registers middleware.

Built-in Middleware


// Parse JSON requests
app.use(express.json());

// Parse URL-encoded form data
app.use(express.urlencoded({ extended: true }));

// Serve static files
app.use(express.static("public"));

Third-Party Middleware


npm install cors morgan
        

const cors = require("cors");
const morgan = require("morgan");

app.use(cors());
app.use(morgan("dev"));
  • cors: Configures Cross-Origin Resource Sharing.
  • morgan: Logs HTTP requests.

8. Express Router

Definition: Express Router creates modular route handlers that can be organized into separate files. This makes large applications easier to maintain.

routes/userRoutes.js


const express = require("express");

const router = express.Router();

router.get("/", (req, res) => {
    res.json({ message: "All users" });
});

router.get("/:id", (req, res) => {
    res.json({ userId: req.params.id });
});

module.exports = router;

app.js


const express = require("express");
const userRoutes = require("./routes/userRoutes");

const app = express();

app.use("/users", userRoutes);

The router now handles requests such as /users and /users/10.

9. Controllers

Definition: Controllers contain the logic used to process requests and produce responses. Separating them from routes keeps route files easier to understand.

controllers/userController.js


exports.getUsers = (req, res) => {
    res.json([
        { id: 1, name: "Tushar" },
        { id: 2, name: "Rahul" }
    ]);
};

routes/userRoutes.js


const express = require("express");
const router = express.Router();

const {
    getUsers
} = require("../controllers/userController");

router.get("/", getUsers);

module.exports = router;

10. HTTP Status Codes

Definition: HTTP status codes indicate whether a request succeeded, failed, or requires further action.

  • 200 OK: Request succeeded.
  • 201 Created: A resource was created.
  • 204 No Content: Request succeeded without a response body.
  • 400 Bad Request: Request data is invalid.
  • 401 Unauthorized: Authentication is missing or invalid.
  • 403 Forbidden: The client lacks permission.
  • 404 Not Found: Resource or route was not found.
  • 409 Conflict: Request conflicts with the current resource state.
  • 422 Unprocessable Content: Request content cannot be processed.
  • 429 Too Many Requests: Rate limit exceeded.
  • 500 Internal Server Error: An unexpected server error occurred.
  • 503 Service Unavailable: The service is temporarily unavailable.

11. Error Handling

Definition: Error-handling middleware catches errors and sends appropriate responses rather than leaving requests unresolved. 


// Route that produces an error
app.get("/error", (req, res, next) => {
    next(new Error("Something went wrong"));
});

// Error-handling middleware
app.use((err, req, res, next) => {
    console.error(err);

    res.status(500).json({
        message: "Internal server error"
    });
});
  • Error middleware uses four parameters: err, req, res, next.
  • Register error-handling middleware after routes.
  • Do not expose stack traces or sensitive internal details to clients in production.

404 Handler


app.use((req, res) => {
    res.status(404).json({
        message: "Route not found"
    });
});

Place the 404 handler after your regular routes and before the error-handling middleware.

12. Async/Await in Routes

Definition: Async route handlers allow asynchronous operations, such as database queries, to be awaited without blocking the event loop. 


app.get("/users", async (req, res, next) => {
    try {
        const users = await getUsersFromDatabase();

        res.json(users);
    } catch (error) {
        next(error);
    }
});

Here, getUsersFromDatabase() represents an asynchronous function you define elsewhere.

In Express 5, rejected Promises returned by route handlers and middleware are automatically forwarded to error handling. In Express 4, use try/catch with next(error) or a compatible async error-handling wrapper.

13. Environment Variables (.env)

Definition: Environment variables store configuration outside your source code, such as port numbers, database connection strings, and secret keys. 


npm install dotenv

.env


PORT=3000
DATABASE_URL=mongodb://127.0.0.1:27017/myapp

app.js


require("dotenv").config();

const PORT = process.env.PORT || 3000;

app.listen(PORT, () => {
    console.log(`Server running on port ${PORT}`);
});

Add .env to .gitignore. Never commit real secrets to a public repository.

14. CORS

Definition: Cross-Origin Resource Sharing (CORS) is a browser security mechanism that controls whether frontend JavaScript can access responses from another origin. 


const cors = require("cors");

app.use(cors({
    origin: "http://localhost:5173"
}));
  • origin: Specifies which origin is allowed.
  • credentials: Enables credentialed cross-origin requests when configured correctly.

Do not combine credentialed requests with a wildcard origin. Configure the allowed frontend origin explicitly when using cookies or other credentials.

15. Cookies

Definition: Cookies are small pieces of data that a server can ask the browser to store and send with subsequent matching requests. 


npm install cookie-parser
        

const cookieParser = require("cookie-parser");

app.use(cookieParser());

app.get("/set-cookie", (req, res) => {
    res.cookie("theme", "dark", {
        httpOnly: true,
        secure: process.env.NODE_ENV === "production",
        sameSite: "lax",
        maxAge: 24 * 60 * 60 * 1000
    });

    res.json({ message: "Cookie set" });
});

app.get("/read-cookie", (req, res) => {
    res.json({
        theme: req.cookies.theme
    });
});

app.get("/clear-cookie", (req, res) => {
    res.clearCookie("theme");

    res.json({ message: "Cookie cleared" });
});
  • httpOnly: Prevents client-side JavaScript from reading the cookie.
  • secure: Sends the cookie only over HTTPS.
  • sameSite: Controls when the browser sends the cookie in cross-site requests.
  • maxAge: Sets the cookie lifetime in milliseconds.

16. Sessions

Definition: A session stores user-specific state across multiple requests. Common session middleware stores a session identifier in a cookie while session data is held server-side. 


npm install express-session
        

const session = require("express-session");

app.use(session({
    secret: process.env.SESSION_SECRET,
    resave: false,
    saveUninitialized: false,
    cookie: {
        httpOnly: true,
        secure: process.env.NODE_ENV === "production",
        sameSite: "lax",
        maxAge: 60 * 60 * 1000
    }
}));

app.post("/login-demo", (req, res) => {
    req.session.userId = "123";

    res.json({ message: "Session created" });
});

app.get("/profile-demo", (req, res) => {
    if (!req.session.userId) {
        return res.status(401).json({
            message: "Not logged in"
        });
    }

    res.json({
        userId: req.session.userId
    });
});

Security note: Set a strong session secret using an environment variable. The default MemoryStore is intended for development, not production. Use a suitable persistent session store in production.

17. Password Hashing

Definition: Password hashing transforms a password into a one-way hash so the original password does not need to be stored in the database. 


npm install bcrypt
        

const bcrypt = require("bcrypt");

async function hashPassword(password) {
    return await bcrypt.hash(password, 12);
}

async function verifyPassword(password, hash) {
    return await bcrypt.compare(password, hash);
}

Store the resulting hash, not the original password. Use appropriate password policies and never log passwords.

18. MongoDB with Mongoose

Definition: Mongoose is an object data modeling library for MongoDB. It provides schemas, models, validation, and methods for interacting with collections. 


npm install mongoose
        

const mongoose = require("mongoose");

async function connectDB() {
    await mongoose.connect(process.env.DATABASE_URL);

    console.log("MongoDB connected");
}

const userSchema = new mongoose.Schema({
    name: {
        type: String,
        required: true
    },
    email: {
        type: String,
        required: true,
        unique: true
    }
});

const User = mongoose.model("User", userSchema);

async function getUsers() {
    return await User.find();
}
  • mongoose.connect(): Connects to MongoDB.
  • Schema: Defines document structure and validation rules.
  • Model: Provides an interface for querying and modifying documents.
  • find(): Retrieves matching documents.
  • findById(): Retrieves a document by its ID.
  • create(): Creates a document.
  • findByIdAndUpdate(): Updates a document by ID.
  • findByIdAndDelete(): Deletes a document by ID.

19. CRUD Operations

Definition: CRUD stands for Create, Read, Update, and Delete. These are the four basic operations commonly used to manage application data. 


// CREATE
const user = await User.create({
    name: "Tushar",
    email: "tushar@example.com"
});

// READ
const users = await User.find();
const singleUser = await User.findById(user._id);

// UPDATE
const updatedUser = await User.findByIdAndUpdate(
    user._id,
    { name: "Updated Name" },
    { new: true, runValidators: true }
);

// DELETE
const deletedUser = await User.findByIdAndDelete(user._id);

These examples require a connected database and a defined Mongoose model. Validate incoming data and handle missing records and database errors in real routes.

20. Authentication and Authorization

Authentication: Verifies who a user is.

Authorization: Determines what an authenticated user is allowed to access or do.

  • Passport.js: Provides authentication strategies for Express applications.
  • Session authentication: Maintains login state using server-side session data.
  • OAuth 2.0: A framework for delegated authorization.
  • OpenID Connect: An identity layer built on OAuth 2.0.
  • JWT: A token format that can carry signed claims.

Never assume that a request is authorized merely because it contains a user ID. Verify authentication and check permissions for protected resources.

21. File Uploads

Definition: File upload middleware processes multipart form data sent by a client. 


npm install multer
        

const multer = require("multer");

const upload = multer({
    dest: "uploads/"
});

app.post("/upload", upload.single("file"), (req, res) => {
    if (!req.file) {
        return res.status(400).json({
            message: "File is required"
        });
    }

    res.json({
        filename: req.file.filename,
        size: req.file.size
    });
});

For production, validate file size and type, restrict acceptable content, and avoid trusting user-supplied filenames. Configure storage and access controls appropriately.

22. Production Best Practices

  • Keep secrets and configuration in environment variables or a secure secret manager.
  • Validate and sanitize incoming data where appropriate.
  • Use HTTPS in production.
  • Use Helmet to set security-related HTTP headers.
  • Apply rate limiting to sensitive endpoints such as login.
  • Use structured logging and centralized error handling.
  • Keep dependencies updated and remove unused packages.
  • Use a persistent database connection and handle startup failures.
  • Do not return database credentials, stack traces, or sensitive internal information to clients.
  • Use a production-ready session store if sessions are required.

npm install helmet express-rate-limit
        

const helmet = require("helmet");
const rateLimit = require("express-rate-limit");

app.use(helmet());

const loginLimiter = rateLimit({
    windowMs: 15 * 60 * 1000,
    limit: 10,
    standardHeaders: "draft-7",
    legacyHeaders: false
});

app.use("/login", loginLimiter);

Adjust rate limits to your application's requirements. Reverse-proxy deployments may also require correctly configuring Express's trust proxy setting.

23. Useful Express Methods

  • app.use(): Registers middleware.
  • app.get(): Handles GET requests.
  • app.post(): Handles POST requests.
  • app.put(): Handles PUT requests.
  • app.patch(): Handles PATCH requests.
  • app.delete(): Handles DELETE requests.
  • app.listen(): Starts the server.
  • express.Router(): Creates a modular router.
  • express.json(): Parses incoming JSON request bodies.
  • express.static(): Serves static files.
  • req.params: Reads route parameters.
  • req.query: Reads query parameters.
  • req.body: Accesses parsed body data.
  • res.json(): Sends JSON.
  • res.status(): Sets the response status code.
  • next(): Passes control to the next handler or error middleware.

24. Important Tips

  • Keep routes, controllers, services, and database models separate as the project grows.
  • Validate request data before saving it.
  • Use async/await for readable asynchronous code.
  • Handle errors centrally and return appropriate status codes.
  • Never store plaintext passwords.
  • Never commit your .env file.
  • Restrict CORS to the origins your application needs.
  • Do not trust user input, uploaded files, or client-provided IDs.
  • Use environment-specific configuration for development and production.
  • Test your endpoints with tools such as Postman or curl.
