Git Cheat Sheet

Git is a version control system that helps developers track changes in their code, collaborate with others, and manage different versions of a project.

1. Configure Git

Definition: Git configuration allows you to set your username and email address. This information is recorded with your commits to identify who made the changes. 


git config --global user.name "Your Name"

git config --global user.email "you@example.com"

git config --list
  • git config: Used to view or change Git settings.
  • --global: Applies the setting to all repositories for your user account.
  • git config --list: Displays the current Git configuration.

2. Create Repository

Definition: A repository (repo) is a place where Git stores project files and tracks their history. The git init command creates a new Git repository in the current directory. 


git init

3. Check Status

Definition: The status command shows which files have been modified, which files are staged for a commit, and which files are not yet tracked by Git. 


git status

4. Add Files

Definition: Adding files means placing changes in the staging area. The staging area allows you to choose which changes will be included in your next commit. 


git add file.txt

git add .

git add *.js
  • git add file.txt: Stages a specific file.
  • git add .: Stages changes in the current directory and its subdirectories.
  • git add *.js: Stages matching JavaScript files in the current directory.

5. Commit

Definition: A commit is a snapshot of the staged changes in your project. Commits help you track the history of your work and understand what changed over time. 


git commit -m "Add new feature"

The -m option lets you add a message describing the changes included in the commit.

6. View Commits

Definition: Git log commands display the commit history of a repository, including commit IDs, authors, dates, and messages. 


git log

git log --oneline
  • git log: Displays detailed commit history.
  • git log --oneline: Displays each commit on a single line.

7. Branches

Definition: A branch is an independent line of development. Branches allow you to work on new features or fix bugs without directly changing the main development branch. 


git branch

git branch feature

git switch feature

git switch -c feature
  • git branch: Lists local branches.
  • git branch feature: Creates a branch named feature.
  • git switch feature: Switches to the feature branch.
  • git switch -c feature: Creates and switches to a new branch.

8. Merge

Definition: Merging combines changes from one branch into another. It is commonly used to integrate a completed feature into the main branch. 


git switch main

git merge feature

In this example, Git switches to the main branch and merges the changes from the feature branch into it.

9. Remote Repository

Definition: A remote repository is a version of your project hosted elsewhere, usually on a service such as GitHub. It allows developers to share and collaborate on code. 


git remote -v

git remote add origin <repository-url>
  • git remote -v: Displays the configured remote repository URLs.
  • git remote add origin: Adds a remote repository with the name origin.

10. Push

Definition: Pushing uploads your local commits to a remote repository so that your changes can be stored and shared online. 


git push origin main

git push -u origin main
  • git push origin main: Pushes local main-branch commits to the remote named origin.
  • git push -u origin main: Pushes the branch and sets its upstream branch for easier future pushes and pulls.

11. Pull

Definition: Pulling downloads changes from a remote repository and integrates them into your current local branch. It typically performs a fetch followed by a merge. 


git pull origin main

12. Clone

Definition: Cloning creates a local copy of an existing remote repository. It downloads the project files and relevant Git history so you can work on the project locally. 


git clone <repository-url>

13. Undo Changes

Definition: Git provides commands to discard unstaged changes or remove files from the staging area without deleting their working-directory changes. 


git restore file.txt

git restore --staged file.txt
  • git restore file.txt: Discards unstaged changes in the specified file, restoring it from the index.
  • git restore --staged file.txt: Removes the file's changes from the staging area while keeping the changes in the working directory.

Warning: The first command can permanently discard uncommitted changes to the specified file. Make sure you do not need those changes before running it.

14. Git Ignore

Definition: A .gitignore file tells Git which untracked files and directories to ignore. It is useful for excluding dependencies, log files, and local configuration files from version control. 


# .gitignore

node_modules/
.env
*.log
  • node_modules/: Ignores the Node.js dependencies directory.
  • .env: Ignores a file commonly used for environment variables.
  • *.log: Ignores files ending in .log.

Security tip: Never commit database passwords, API keys, access tokens, or other secrets to a public GitHub repository. If a secret is committed, removing it from the latest version may not remove it from the repository's history. Revoke or rotate the exposed secret immediately.

15. Git vs GitHub

Git: A version control system that tracks changes in files on your computer.

GitHub: An online platform for hosting Git repositories and collaborating with other developers.

Git can be used without GitHub, but GitHub uses Git to manage repository history and collaboration.
