MongoDB Cheat Sheet

A quick reference for MongoDB commands, CRUD operations, query operators, aggregation, indexes, Mongoose, and backend development.

1. What Is MongoDB?

MongoDB is a NoSQL database that stores data in flexible, JSON-like documents using BSON internally. Unlike relational databases, MongoDB organizes documents into collections instead of storing data in tables and rows.

Important terminology:

  • Database: A container for collections.
  • Collection: A group of documents, similar to a table in SQL.
  • Document: A set of fields and values, similar to a JSON object.
  • Field: A named property inside a document.
  • _id: The unique identifier of a document. MongoDB generates one automatically if it is omitted.
  • BSON: A binary representation of JSON-like documents that supports additional data types.
{
"_id": ObjectId("507f1f77bcf86cd799439011"),
"name": "Tushar",
"age": 24,
"city": "Chandigarh"

}

2. Start MongoDB Shell

mongosh is the command-line shell used to connect to MongoDB and execute database commands. 

// Connect to the default local MongoDB instance

mongosh

// Connect using a connection string
mongosh "mongodb://127.0.0.1:27017"

// Connect to a specific database
mongosh "mongodb://127.0.0.1:27017/myDatabase"

3. Database Commands

A database organizes related collections. These commands help you select, inspect, and delete databases. 

// Show all databases

show dbs

// Switch to or select a database
use myDatabase

// Show the current database
db

// Delete the current database
db.dropDatabase()

Note: Running use myDatabase selects the database but does not necessarily create it on disk. A database is generally created when data is first stored.

4. Collection Commands

A collection stores related documents. MongoDB can create collections automatically when you first insert data, or you can create them explicitly. 

// Show collections

show collections

// Create a collection
db.createCollection("users")

// Delete a collection
db.users.drop()

// Rename a collection
db.users.renameCollection("customers")

5. What Is CRUD?

CRUD stands for Create, Read, Update, and Delete. These are the four fundamental operations used to manage database records.

  • Create: Insert new documents.
  • Read: Retrieve existing documents.
  • Update: Modify existing documents.
  • Delete: Remove documents.

6. Insert Documents

Insert operations add new documents to a collection. MongoDB generates an _id when one is not supplied. 

// Insert one document

db.users.insertOne({
name: "Tushar",
age: 24,
city: "Chandigarh"
})

// Insert multiple documents
db.users.insertMany([
{ name: "Aman", age: 22 },
{ name: "Rahul", age: 25 }
])

7. Find Documents

Read operations retrieve documents that match a query filter. An empty filter, {}, matches all documents. 

// Find all documents

db.users.find()

// Find one matching document
db.users.findOne({ name: "Tushar" })

// Filter documents
db.users.find({ age: 24 })

// Select specific fields (projection)
db.users.find(
{},
{ name: 1, age: 1, _id: 0 }
)

// Sort ascending by age
db.users.find().sort({ age: 1 })

// Sort descending by age
db.users.find().sort({ age: -1 })

// Limit the results
db.users.find().limit(5)

// Skip the first five documents
db.users.find().skip(5)

// Combine filtering, sorting, and limiting
db.users.find({ age: { $gte: 18 } })
.sort({ age: 1 })
.limit(10)

Projection: Controls which fields are returned. Use 1 to include a field and 0 to exclude it. Generally, inclusion and exclusion cannot be mixed in the same projection, except for excluding _id.

8. Query Operators

Query operators allow you to filter documents based on comparisons, logical conditions, and the values contained in fields.

Comparison Operators

// Equal to

db.users.find({ age: { $eq: 24 } })

// Not equal to
db.users.find({ age: { $ne: 24 } })

// Greater than
db.users.find({ age: { $gt: 20 } })

// Greater than or equal to
db.users.find({ age: { $gte: 20 } })

// Less than
db.users.find({ age: { $lt: 30 } })

// Less than or equal to
db.users.find({ age: { $lte: 30 } })

// Match any listed value
db.users.find({
city: { $in: ["Delhi", "Chandigarh"] }
})

// Match none of the listed values
db.users.find({
city: { $nin: ["Delhi", "Chandigarh"] }
})

Logical Operators

// AND: all conditions must match

db.users.find({
age: { $gte: 18 },
city: "Chandigarh"
})

// OR: at least one condition must match
db.users.find({
$or: [
{ age: 18 },
{ city: "Delhi" }
]
})

// NOT: documents that do not satisfy the condition
db.users.find({
age: { $not: { $gt: 30 } }
})

// NOR: none of the conditions may match
db.users.find({
$nor: [
{ city: "Delhi" },
{ age: 18 }
]
})

Element and Array Operators

// Field exists

db.users.find({ email: { $exists: true } })

// Field has a specific BSON type
db.users.find({ age: { $type: "number" } })

// Match an array containing a value
db.users.find({ hobbies: "coding" })

// Match an array containing all listed values
db.users.find({
skills: { $all: ["JavaScript", "Node.js"] }
})

// Match arrays with a specified number of elements
db.users.find({
hobbies: { $size: 3 }
})

Note: The $size operator matches an exact array length. It does not directly support a range of array lengths.

9. Update Documents

Update operations modify fields in existing documents. Update operators let you change selected fields without replacing the entire document. 

// Update one matching document

db.users.updateOne(
{ name: "Tushar" },
{ $set: { age: 25 } }
)

// Update multiple matching documents
db.users.updateMany(
{ city: "Delhi" },
{ $set: { city: "New Delhi" } }
)

// Increment a numeric field
db.users.updateOne(
{ name: "Tushar" },
{ $inc: { age: 1 } }
)

// Remove a field
db.users.updateOne(
{ name: "Tushar" },
{ $unset: { city: "" } }
)

// Add a value to an array if it is not already present
db.users.updateOne(
{ name: "Tushar" },
{ $addToSet: { skills: "JavaScript" } }
)

// Add a value to an array
db.users.updateOne(
{ name: "Tushar" },
{ $push: { skills: "Node.js" } }
)

// Upsert: insert a document if no document matches
db.users.updateOne(
{ email: "user@example.com" },
{ $set: { name: "Aman" } },
{ upsert: true }
)

Upsert: When set to true, MongoDB inserts a document if no document matches the filter. Otherwise, it updates the matching document.

10. Replace Documents

replaceOne() replaces the contents of one matching document with a new document, apart from its immutable _id. Unlike $set, it replaces the other existing fields too. 

db.users.replaceOne(
{ name: "Tushar" },
{
    name: "Tushar",
    age: 25,
    city: "Chandigarh"
}

)

11. Delete Documents

Delete operations permanently remove matching documents from a collection. 

// Delete one matching document

db.users.deleteOne({ name: "Tushar" })

// Delete all matching documents
db.users.deleteMany({ age: { $lt: 18 } })

// Delete every document in the collection
db.users.deleteMany({})

Warning: An empty filter in deleteMany({}) deletes all documents in the collection. Double-check filters before running destructive operations.

12. Count and Distinct

Counting returns the number of matching documents. Distinct returns unique values for a specified field. 

// Count all documents

db.users.countDocuments({})

// Count matching documents
db.users.countDocuments({ age: 24 })

// Get distinct city values
db.users.distinct("city")

// Get distinct city values matching a filter
db.users.distinct("city", { age: { $gte: 18 } })

13. Aggregation Pipeline

Aggregation processes documents through a sequence of stages. Each stage filters, groups, sorts, transforms, or summarizes data.

  • $match: Filters documents.
  • $group: Groups documents and calculates values.
  • $project: Selects or computes output fields.
  • $sort: Sorts documents.
  • $limit: Limits the number of documents.
  • $skip: Skips a number of documents.
  • $unwind: Produces a document for each array element.
  • $count: Counts documents entering that stage.
// Group users by city

db.users.aggregate([
{
$group: {
_id: "$city",
totalUsers: { $sum: 1 }
}
}
])

// Filter and calculate average age by city
db.users.aggregate([
{ $match: { age: { $gte: 18 } } },
{
$group: {
_id: "$city",
averageAge: { $avg: "$age" }
}
}
])

// Sort by age, newest/highest first
db.users.aggregate([
{ $sort: { age: -1 } }
])

// Count matching documents
db.users.aggregate([
{ $match: { age: { $gte: 18 } } },
{ $count: "adultUsers" }
])

// Select fields and calculate a new field
db.users.aggregate([
{
$project: {
name: 1,
age: 1,
isAdult: { $gte: ["$age", 18] }
}
}
])

14. Indexes

An index is a data structure that helps MongoDB find documents more efficiently. Indexes can improve read performance but require additional storage and can slow down writes. 

// Create an ascending index

db.users.createIndex({ name: 1 })

// Create a descending index
db.users.createIndex({ age: -1 })

// Create a compound index
db.users.createIndex({ city: 1, age: -1 })

// Create a unique index
db.users.createIndex(
{ email: 1 },
{ unique: true }
)

// List indexes
db.users.getIndexes()

// Drop an index by name
db.users.dropIndex("name_1")

// Inspect a query execution plan
db.users.find({ name: "Tushar" }).explain("executionStats")

Index direction: 1 means ascending and -1 means descending. Compound index field order matters because it affects which queries the index can support efficiently.

15. Schema Design: Embedded vs Referenced Data

MongoDB has a flexible document model, but a good schema design is still important. Related data can be embedded inside a document or stored separately and referenced.

Embedded Documents

Embedding stores related information inside the same document. It can be convenient when the data is usually read together. 

{
name: "Tushar",
address: {
    city: "Chandigarh",
    country: "India"
}

}

Referenced Documents

Referencing stores related information in separate documents and connects them using identifiers. It can be useful for shared or independently managed data. 

// User document

{
_id: ObjectId("507f1f77bcf86cd799439011"),
name: "Tushar"
}

// Order document
{
userId: ObjectId("507f1f77bcf86cd799439011"),
total: 1500
}

Choose embedding or referencing according to access patterns, document growth, duplication, and consistency requirements.

16. Schema Validation

Schema validation enforces rules on documents written to a collection. It helps prevent invalid data from being stored. 

db.createCollection("products", {
validator: {
    $jsonSchema: {
        bsonType: "object",
        required: ["name", "price"],
        properties: {
            name: {
                bsonType: "string"
            },
            price: {
                bsonType: "number",
                minimum: 0
            }
        }
    }
}

})

17. What Is Mongoose?

Mongoose is an Object Data Modeling (ODM) library for Node.js. It provides schemas, models, validation, middleware, and convenient methods for working with MongoDB.

MongoDB itself does not require Mongoose. You can also connect to MongoDB from Node.js using the official MongoDB Node.js driver.

18. Install Mongoose

Run this command inside your Node.js project directory. 

npm install mongoose

19. Connect Using Mongoose

mongoose.connect() connects your application to a MongoDB database using a connection string. 

const mongoose = require("mongoose");

async function connectDB() {
try {
await mongoose.connect(process.env.MONGODB_URI);
console.log("MongoDB connected");
} catch (error) {
console.error("MongoDB connection failed:", error);
process.exit(1);
}
}

module.exports = connectDB;

Put your connection string in an environment variable and load it before calling connectDB().

20. Environment Variables

Environment variables keep configuration separate from source code. They are especially important for database usernames, passwords, and hosted database connection strings. 

// Install dotenv if your project uses it

npm install dotenv

// .env
MONGODB_URI=mongodb://127.0.0.1:27017/myDatabase

// CommonJS entry file
require("dotenv").config();

const connectDB = require("./config/db");

connectDB();

Add .env to .gitignore so that credentials are not accidentally committed to a public repository.

21. Create a Mongoose Schema and Model

A schema defines the structure, data types, validation rules, and other behavior of documents managed by a Mongoose model. A model provides methods for querying and modifying documents. 

const mongoose = require("mongoose");

const userSchema = new mongoose.Schema({
name: {
type: String,
required: true,
trim: true
},
age: {
type: Number,
min: 0
},
email: {
type: String,
required: true,
unique: true,
lowercase: true,
trim: true
}
}, {
timestamps: true
});

const User = mongoose.model("User", userSchema);

module.exports = User;

timestamps: Automatically adds createdAt and updatedAt fields. unique: Declares a unique index; it is not a normal Mongoose validator, so duplicate values can cause a MongoDB duplicate-key error.

22. Mongoose CRUD Operations

Mongoose models provide methods for creating, reading, updating, and deleting documents. The examples below assume a model named User and an existing variable named userId. 

// Create a document

const user = await User.create({
name: "Tushar",
age: 24,
email: "tushar@example.com"
});

// Read all documents
const users = await User.find();

// Read one document
const foundUser = await User.findOne({
name: "Tushar"
});

// Find by ID
const userById = await User.findById(userId);

// Select specific fields
const names = await User.find().select("name email");

// Update one document
await User.updateOne(
{ _id: userId },
{ $set: { age: 25 } },
{ runValidators: true }
);

// Find and update a document
const updatedUser = await User.findByIdAndUpdate(
userId,
{ age: 25 },
{ returnDocument: "after", runValidators: true }
);

// Delete one document
await User.deleteOne({ _id: userId });

Important: Run these operations inside an async function or an async route handler. Mongoose update validators are not enabled by default for every update operation, so use runValidators: true when appropriate.

23. Mongoose Populate

populate() replaces a referenced document ID with the corresponding document data when querying. It is useful when related data is stored in separate collections. 

const postSchema = new mongoose.Schema({
title: {
    type: String,
    required: true
},
author: {
    type: mongoose.Schema.Types.ObjectId,
    ref: "User",
    required: true
}

});

const Post = mongoose.model("Post", postSchema);

// Retrieve a post and its author
const post = await Post.findById(postId)
.populate("author", "name email");

24. Mongoose Relationships

A relationship connects documents that belong together. Mongoose commonly represents references using Schema.Types.ObjectId. 

const orderSchema = new mongoose.Schema({
total: {
    type: Number,
    required: true,
    min: 0
},
user: {
    type: mongoose.Schema.Types.ObjectId,
    ref: "User",
    required: true
}

});

const Order = mongoose.model("Order", orderSchema);

// Find orders and their associated users
const orders = await Order.find().populate("user", "name email");

25. Transactions

A transaction allows multiple database operations to succeed or fail together. Transactions require a suitable MongoDB deployment, such as a replica set or sharded cluster. 

const session = await mongoose.startSession();

try {
await session.withTransaction(async () => {
await User.updateOne(
{ _id: userId },
{ $inc: { balance: -100 } },
{ session }
);

    await User.updateOne(
        { _id: recipientId },
        { $inc: { balance: 100 } },
        { session }
    );
});

} finally {
await session.endSession();
}

This example demonstrates transaction syntax only. A real money-transfer system also needs balance checks, authorization, concurrency safeguards, and appropriate error handling.

26. Pagination

Pagination splits a large result set into smaller portions. Skip/limit pagination is simple, while cursor-based pagination can be more efficient for large datasets. 

// Page-based pagination

const page = 2;
const limit = 10;

const users = await User.find()
.sort({ _id: 1 })
.skip((page - 1) * limit)
.limit(limit);

// Count matching documents
const totalUsers = await User.countDocuments({});

27. Query Performance

Query optimization reduces unnecessary database work and improves response times as your application grows. 

// Inspect query execution statistics

db.users.find({ city: "Chandigarh" })
.explain("executionStats")

// Select only required fields
db.users.find(
{ city: "Chandigarh" },
{ name: 1, email: 1, _id: 0 }
)

// Limit returned documents
db.users.find({ city: "Chandigarh" }).limit(20)
  • Create indexes for frequently queried fields when justified by query patterns.
  • Use projections to avoid retrieving unnecessary fields.
  • Limit result sizes and paginate large result sets.
  • Use explain() to understand query execution.
  • Avoid creating too many indexes because indexes consume storage and add write overhead.

28. MongoDB Security Best Practices

  • Use authentication and least-privilege database accounts.
  • Never expose database credentials in frontend JavaScript.
  • Keep connection strings and secrets out of public repositories.
  • Restrict network access to trusted application servers.
  • Validate incoming data on the server.
  • Do not pass untrusted request objects directly into database filters.
  • Use backups and test your recovery process.
  • Keep MongoDB and its drivers updated.

Safe Query Example in Express

// Avoid passing the entire request body as a filter:

// User.find(req.body);

// Prefer explicitly selecting allowed fields:
const filter = {
email: req.body.email
};

const user = await User.findOne(filter);

29. MongoDB Connection Strings

A connection string specifies how your application connects to MongoDB. Local and hosted MongoDB deployments use different connection details. 

// Local MongoDB

mongodb://127.0.0.1:27017/myDatabase

// Environment variable example
MONGODB_URI=mongodb://127.0.0.1:27017/myDatabase

// Hosted MongoDB example format
MONGODB_URI=mongodb+srv://USERNAME:PASSWORD@CLUSTER_HOST/myDatabase

Replace the placeholders with your actual hosted database details. Never publish a real connection string containing credentials.

30. Common MongoDB Mistakes

  • Forgetting that MongoDB queries use BSON types, which can differ from ordinary strings.
  • Using a string where an ObjectId is expected.
  • Updating a document without the intended filter.
  • Deleting documents using an empty filter accidentally.
  • Assuming unique: true is a regular Mongoose validator.
  • Creating indexes without considering query patterns and write overhead.
  • Storing credentials in public code or frontend files.
  • Returning entire collections without pagination.

31. Quick Reference

  • find() — Retrieve matching documents.
  • insertOne() — Insert one document.
  • insertMany() — Insert multiple documents.
  • updateOne() — Update one matching document.
  • updateMany() — Update multiple matching documents.
  • replaceOne() — Replace one matching document.
  • deleteOne() — Delete one matching document.
  • deleteMany() — Delete multiple matching documents.
  • aggregate() — Process documents through an aggregation pipeline.
  • createIndex() — Create an index.
  • countDocuments() — Count matching documents.
  • distinct() — Retrieve distinct field values.
  • populate() — Load referenced documents using Mongoose.
  • mongoose.connect() — Connect a Mongoose application to MongoDB.
