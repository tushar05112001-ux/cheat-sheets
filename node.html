Node.js Cheat Sheet

A quick reference for Node.js fundamentals, modules, asynchronous programming, file handling, npm, HTTP servers, streams, and backend development.

1. What Is Node.js?

Node.js is a JavaScript runtime that allows JavaScript to run outside the browser. It is commonly used to build APIs, web servers, command-line tools, and backend applications.

  • Runtime: An environment that executes a program.
  • V8: The JavaScript engine used by Node.js.
  • Event loop: Coordinates callbacks and asynchronous work.
  • Non-blocking I/O: Allows Node.js to continue processing other work while many I/O operations are pending.
  • npm: The standard package manager commonly installed with Node.js.

2. Installation and Basic Commands

Install Node.js from its official website. For most projects, choose a supported LTS release. 

// Check Node.js version

node --version

// Check npm version
npm --version

// Run a JavaScript file
node app.js

// Run a file using the Node.js inspector
node --inspect app.js

// Display Node.js command help
node --help

3. Node.js REPL

REPL stands for Read-Eval-Print Loop. It lets you execute JavaScript expressions interactively in the terminal. 

// Start the REPL

node

// Try JavaScript expressions
2 + 3

const name = "Tushar";
console.log(name);

// Exit the REPL
.exit

4. Create a Node.js Project

A Node.js project commonly uses package.json to define metadata, scripts, dependencies, and package configuration. 

// Create a project directory

mkdir my-app
cd my-app

// Generate package.json
npm init -y

// Install a package
npm install express

// Install a development dependency
npm install --save-dev nodemon

// Run a package script
npm run start

Add scripts to package.json when you want consistent commands for starting, testing, and developing your application. 

{
"scripts": {
    "start": "node app.js",
    "dev": "nodemon app.js"
}

}

5. What Are Modules?

Modules let you organize code into reusable files. Node.js supports CommonJS and ECMAScript modules (ESM).

CommonJS

CommonJS uses require() to import modules and module.exports to export values. 

// math.js

function add(a, b) {
return a + b;
}

module.exports = { add };

// app.js
const { add } = require("./math");

console.log(add(5, 3));

ES Modules (ESM)

ESM uses the import and export keywords. It is the standard JavaScript module system. 

// math.js

export function add(a, b) {
return a + b;
}

// app.js
import { add } from "./math.js";

console.log(add(5, 3));

To use ESM consistently in a Node.js project, add "type": "module" to package.json, or use the .mjs extension. 

{
"type": "module"

}

In an ESM file, use import.meta.url when you need information about the current module. CommonJS-specific variables such as __dirname and __filename are not directly available in ordinary ESM files.

6. Useful Node.js Globals

Globals are values or functions available without explicitly importing them. Some familiar names differ between CommonJS and ESM. 

// Current working directory

console.log(process.cwd());

// Node.js version
console.log(process.version);

// Platform
console.log(process.platform);

// Environment variables
console.log(process.env.NODE_ENV);

// Current file in CommonJS
console.log(__filename);
console.log(__dirname);

// Global object
console.log(globalThis);

Note: __filename and __dirname are available in CommonJS modules. In ESM, derive paths from import.meta.url when needed.

7. The process Object

The process object provides information and control over the currently running Node.js process. 

// Read command-line arguments

console.log(process.argv);

// Read an environment variable
console.log(process.env.PORT);

// Exit with a success code
process.exit(0);

// Exit with an error code
process.exit(1);

// Listen for a process signal
process.on("SIGINT", () => {
console.log("Received Ctrl+C");
process.exit(0);
});

Avoid calling process.exit() unnecessarily because it can terminate pending asynchronous operations. Prefer allowing the process to finish naturally when practical.

8. Environment Variables

Environment variables store configuration separately from source code. They are useful for ports, database connection strings, API keys, and environment-specific settings. 

// .env

PORT=5000
NODE_ENV=development
// Start Node.js with environment variables from a file

node --env-file=.env app.js

Recent Node.js versions support the --env-file option. Another common approach is the dotenv package. 

// Install dotenv

npm install dotenv

// CommonJS
require("dotenv").config();

// ESM
import "dotenv/config";

// Read the variable
const port = process.env.PORT || 3000;

Never commit real secrets to a public repository. Add files containing credentials, such as .env, to .gitignore.

9. The path Module

The built-in node:path module provides utilities for working with file and directory paths across operating systems. 

import path from "node:path";

// Join path segments safely
const filePath = path.join("public", "images", "logo.png");

// Get the file name
console.log(path.basename(filePath));

// Get the extension
console.log(path.extname(filePath));

// Get the directory
console.log(path.dirname(filePath));

// Resolve an absolute path
console.log(path.resolve("data", "users.json"));

10. File System (fs)

The built-in node:fs module lets you create, read, update, and delete files and directories.

Asynchronous File Operations

import { readFile, writeFile, appendFile } from "node:fs/promises";

// Write a file
await writeFile("message.txt", "Hello Node.js");

// Read a file
const content = await readFile("message.txt", "utf8");
console.log(content);

// Append content
await appendFile("message.txt", "\nNew line");

// Read a file as a Buffer
const buffer = await readFile("message.txt");
console.log(buffer);

Directory Operations

import {
mkdir,
readdir,
rename,
unlink

} from "node:fs/promises";

// Create a directory
await mkdir("uploads", { recursive: true });

// List directory contents
console.log(await readdir("."));

// Rename a file
await rename("old.txt", "new.txt");

// Delete a file
await unlink("new.txt");

Prefer asynchronous file operations in servers when appropriate. Synchronous methods such as readFileSync() block the JavaScript thread while the operation runs.

11. The URL Module

The built-in URL API parses and constructs URLs. It is useful for reading query parameters and working with request addresses. 

const url = new URL(
"https://example.com/products?page=2&sort=price"

);

console.log(url.hostname);
console.log(url.pathname);
console.log(url.searchParams.get("page"));
console.log(url.searchParams.get("sort"));

// Add a query parameter
url.searchParams.set("category", "books");

console.log(url.toString());

12. Synchronous vs Asynchronous Code

Synchronous code executes an operation and waits for it to finish before continuing. Asynchronous code allows the program to make progress while waiting for operations such as network requests or file I/O. 

// Synchronous operation

import { readFileSync } from "node:fs";

const data = readFileSync("message.txt", "utf8");
console.log(data);

// Asynchronous operation
import { readFile } from "node:fs/promises";

const dataAsync = await readFile("message.txt", "utf8");
console.log(dataAsync);

13. Callbacks

A callback is a function passed to another function to be called later. Many Node.js APIs support callbacks, including older file-system APIs. 

import { readFile } from "node:fs";

readFile("message.txt", "utf8", (error, data) => {
if (error) {
console.error(error);
return;
}

console.log(data);

});

This is an example of the error-first callback pattern: the first argument represents an error, or is null when successful.

14. Promises

A Promise represents the eventual success or failure of an asynchronous operation. Its states are pending, fulfilled, and rejected. 

const promise = new Promise((resolve, reject) => {
const success = true;

if (success) {
    resolve("Operation successful");
} else {
    reject(new Error("Operation failed"));
}

});

promise
.then(result => console.log(result))
.catch(error => console.error(error))
.finally(() => console.log("Finished"));

15. async and await

async declares a function that returns a Promise. await pauses that async function until a Promise settles, making asynchronous code easier to read. 

async function getData() {
try {
    const response = await fetch(
        "https://jsonplaceholder.typicode.com/posts/1"
    );

    if (!response.ok) {
        throw new Error(`HTTP error: ${response.status}`);
    }

    const data = await response.json();
    console.log(data);
} catch (error) {
    console.error("Request failed:", error);
}

}

getData();

Tip: Independent asynchronous tasks can often run concurrently using Promise.all(). 

const [users, posts] = await Promise.all([
fetchUsers(),
fetchPosts()

]);

16. Event Loop

The event loop coordinates JavaScript execution and asynchronous callbacks. Node.js also uses operating-system facilities and a worker pool for certain operations. A long-running CPU-bound JavaScript function can block the event loop. 

console.log("First");

setTimeout(() => {
console.log("Timer callback");
}, 0);

Promise.resolve().then(() => {
console.log("Promise callback");
});

console.log("Last");

// Typical output:
// First
// Last
// Promise callback
// Timer callback

The exact scheduling behavior depends on the APIs and context, but synchronous statements execute before these scheduled callbacks.

17. EventEmitter

EventEmitter allows objects to emit named events and notify registered listeners. It is widely used in Node.js APIs. 

import { EventEmitter } from "node:events";

const emitter = new EventEmitter();

emitter.on("message", message => {
console.log("Received:", message);
});

emitter.emit("message", "Hello Node.js");

// Remove all listeners for an event
emitter.removeAllListeners("message");

An emitted error event on an EventEmitter without an appropriate listener can terminate the process. Handle error events where required by the API.

18. Create an HTTP Server

The built-in node:http module lets you create an HTTP server without a framework. Express.js is built on Node.js HTTP capabilities and simplifies routing and middleware. 

import { createServer } from "node:http";

const server = createServer((req, res) => {
res.writeHead(200, {
"Content-Type": "text/plain; charset=utf-8"
});

res.end("Hello from Node.js!");

});

server.listen(3000, () => {
console.log("Server running on port 3000");
});

19. Handling HTTP Requests

The request object contains information about an incoming request, including its HTTP method, URL, and headers. The response object is used to send status codes, headers, and response data. 

import { createServer } from "node:http";

const server = createServer((req, res) => {
const url = new URL(
req.url,
"http://${req.headers.host || "localhost"}"
);

if (req.method === "GET" && url.pathname === "/") {
    res.writeHead(200, {
        "Content-Type": "text/plain; charset=utf-8"
    });

    res.end("Home page");
    return;
}

if (req.method === "GET" && url.pathname === "/about") {
    res.writeHead(200, {
        "Content-Type": "application/json"
    });

    res.end(JSON.stringify({
        page: "About",
        success: true
    }));

    return;
}

res.writeHead(404, {
    "Content-Type": "application/json"
});

res.end(JSON.stringify({
    error: "Not found"
}));

});

server.listen(3000);

20. JSON

JSON is a text format used to exchange structured data. JavaScript provides methods to convert between JSON strings and values. 

const user = {
name: "Tushar",
age: 24

};

// JavaScript object to JSON string
const json = JSON.stringify(user);

// JSON string to JavaScript object
const parsedUser = JSON.parse(json);

console.log(json);
console.log(parsedUser.name);

21. Buffer

A Buffer represents a sequence of bytes. It is useful for binary data, file contents, network protocols, and streams. 

// Create a Buffer from text

const buffer = Buffer.from("Hello Node.js", "utf8");

// Convert a Buffer to text
console.log(buffer.toString("utf8"));

// Check its size in bytes
console.log(buffer.length);

// Allocate a zero-filled Buffer
const data = Buffer.alloc(10);

Avoid using Buffer.allocUnsafe() unless you understand its behavior and ensure the allocated memory is initialized before use.

22. Streams

Streams process data incrementally instead of requiring an entire dataset to be loaded into memory. They are useful for large files, network communication, and continuous data processing.

  • Readable: Provides data to be consumed.
  • Writable: Accepts data to be written.
  • Duplex: Supports both reading and writing.
  • Transform: Reads data, transforms it, and writes the result.
import { createReadStream, createWriteStream } from "node:fs";

import { pipeline } from "node:stream/promises";

await pipeline(
createReadStream("large-file.txt"),
createWriteStream("copy.txt")
);

console.log("File copied");

pipeline() handles stream errors and coordinates the stream lifecycle more safely than manually connecting streams without proper error handling.

23. Child Processes

Child processes allow Node.js to execute external programs or separate processes. They are useful for running command-line tools and CPU-intensive tasks that should not block the main JavaScript thread. 

import { execFile } from "node:child_process";

execFile("node", ["--version"], (error, stdout, stderr) => {
if (error) {
console.error(error);
return;
}

console.log(stdout);
console.error(stderr);

});

Prefer argument arrays with APIs such as execFile() when executing programs with dynamic input. Avoid passing untrusted input into shell commands.

24. Worker Threads

Worker threads run JavaScript in separate threads. They can help with CPU-intensive work that would otherwise block the main event loop. They are not normally needed for ordinary asynchronous I/O. 

// worker.js

import { parentPort } from "node:worker_threads";

parentPort.postMessage("Hello from worker");

// main.js
import { Worker } from "node:worker_threads";

const worker = new Worker(
new URL("./worker.js", import.meta.url)
);

worker.on("message", message => {
console.log(message);
});

worker.on("error", error => {
console.error(error);
});

worker.on("exit", code => {
console.log("Worker exited:", code);
});

25. Cryptography

Node.js includes the node:crypto module for cryptographic operations. Use appropriate password-hashing algorithms for passwords rather than fast general-purpose hashes such as SHA-256 alone. 

import { randomBytes, randomUUID } from "node:crypto";

// Generate a random identifier
console.log(randomUUID());

// Generate random bytes
const token = randomBytes(32).toString("hex");

console.log(token);

For password storage, use a dedicated password-hashing algorithm such as Argon2id, scrypt, or bcrypt with suitable parameters. Never store plaintext passwords.

26. OS Module

The node:os module provides information about the operating system and the machine running Node.js. 

import os from "node:os";

// Operating system platform
console.log(os.platform());

// CPU architecture
console.log(os.arch());

// Number of logical CPUs
console.log(os.cpus().length);

// Free memory in bytes
console.log(os.freemem());

// Total memory in bytes
console.log(os.totalmem());

// System uptime in seconds
console.log(os.uptime());

27. Timers

Timers schedule callbacks to run after a delay, on a later event-loop iteration, or repeatedly. 

// Run once after a delay

const timeout = setTimeout(() => {
console.log("Executed");
}, 1000);

// Cancel the timeout
clearTimeout(timeout);

// Run repeatedly
const interval = setInterval(() => {
console.log("Repeated");
}, 1000);

// Cancel the interval
clearInterval(interval);

// Run on a later event-loop iteration
setImmediate(() => {
console.log("Immediate callback");
});

28. npm and Package Management

npm manages dependencies, versions, and scripts for Node.js projects. The lockfile records the resolved dependency tree for more reproducible installs. 

// Install a package

npm install express

// Install a development dependency
npm install --save-dev nodemon

// Remove a package
npm uninstall express

// Install dependencies from package.json and the lockfile
npm ci

// Update dependencies within package.json version ranges
npm update

// List installed packages
npm list

// Run a script from package.json
npm run dev

// Run package-provided commands
npx nodemon app.js

Commit package-lock.json for applications using npm. Use npm ci in automated builds when you want installation to follow the committed lockfile.

29. Error Handling

Errors represent failures during execution. Handle expected failures deliberately and avoid exposing internal details to users. 

// Synchronous error handling

try {
JSON.parse("{ invalid json }");
} catch (error) {
console.error("Invalid JSON:", error.message);
}

// Asynchronous error handling
async function loadFile() {
try {
const data = await readFile("missing.txt", "utf8");
return data;
} catch (error) {
console.error("Unable to read file:", error.message);
throw error;
}
}

In a server, make sure rejected Promises are handled. Log useful diagnostic information securely and return appropriate responses instead of exposing stack traces to clients.

30. Debugging

Node.js supports debugging through the inspector protocol. You can use browser developer tools or an editor such as VS Code. 

// Start the inspector

node --inspect app.js

// Pause at the first line of user code
node --inspect-brk app.js

// Enable built-in test runner
node --test

31. Testing

Tests verify that code behaves as expected and help catch regressions. Node.js provides a built-in test runner. 

// math.js

export function add(a, b) {
return a + b;
}

// math.test.js
import test from "node:test";
import assert from "node:assert/strict";
import { add } from "./math.js";

test("add returns the sum", () => {
assert.equal(add(2, 3), 5);
});

// Run tests
// node --test

32. Security Best Practices

  • Use a supported Node.js release.
  • Keep dependencies updated and review security advisories.
  • Never commit API keys, passwords, or private certificates.
  • Validate and normalize untrusted input.
  • Avoid executing shell commands with unsanitized input.
  • Use HTTPS for production network traffic.
  • Apply authentication, authorization, and rate limiting where appropriate.
  • Do not expose internal error details in production responses.
  • Set timeouts and sensible resource limits for incoming requests.
  • Handle shutdown signals and release resources cleanly.

33. Node.js Best Practices

  • Use asynchronous APIs for I/O-heavy server workloads when appropriate.
  • Keep CPU-intensive work from blocking the event loop.
  • Split applications into focused modules.
  • Use environment variables for configuration.
  • Use a lockfile for repeatable dependency installation.
  • Handle errors consistently.
  • Use streams for large files or continuous data.
  • Validate request data before using it.
  • Write tests for important application behavior.
  • Use logging and monitoring in production.
