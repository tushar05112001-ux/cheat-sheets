React Cheat Sheet

A quick reference to modern React: components, JSX, props, Hooks, forms, routing, API requests, performance, and React 19 features.

1. What Is React?

React is a JavaScript library for building user interfaces. It lets you create reusable UI components and update the interface when data changes.

  • Component: A reusable piece of the user interface.
  • JSX: A syntax extension that lets you write HTML-like markup in JavaScript.
  • Props: Inputs passed from a parent component to a child component.
  • State: Data managed by a component that can trigger a re-render when updated.
  • Hooks: Functions such as useState and useEffect that let function components use React features.

2. Create a React Project with Vite

Vite provides a development server and build tools for React projects. Create React App is deprecated for new projects, so Vite is a common lightweight choice. React also recommends considering frameworks for applications that need built-in routing, server rendering, or other production features. 

// Create a React project

npm create vite@latest my-app -- --template react

// Enter the project directory
cd my-app

// Install dependencies
npm install

// Start the development server
npm run dev

// Create a production build
npm run build

// Preview the production build
npm run preview

For TypeScript, use --template react-ts instead of --template react.

5. JSX

JSX lets you describe UI using HTML-like syntax inside JavaScript. JSX is transformed into JavaScript by your build tooling. 

const name = "Tushar";

JSX rules:

  • Return one root element, or use a Fragment: <>...</>.
  • Close all tags, including <img /> and <input />.
  • Use className instead of HTML's class.
  • Use curly braces {} to embed JavaScript expressions.
  • Use camelCase for most DOM event and property names, such as onClick.

9. useState

useState adds state to a function component. Updating state requests a re-render so the UI can reflect the new value. 

import { useState } from "react";

function Counter() {
const [count, setCount] = useState(0);

function increment() {
    setCount(previousCount => previousCount + 1);
}

return (
    <button onClick={increment}>
        Count: {count}
    </button>
);

}

export default Counter;

Syntax:

const [state, setState] = useState(initialValue);

Use the functional update form when the next value depends on the previous state. Do not mutate objects or arrays stored in state directly.

14. Controlled Forms

A controlled input gets its value from React state and updates that state through an event handler. This gives React control over the current input value. 

import { useState } from "react";

function LoginForm() {
const [email, setEmail] = useState("");

function handleSubmit(event) {
    event.preventDefault();
    console.log("Submitted:", email);
}

return (
    <form onSubmit={handleSubmit}>
        <input
            type="email"
            value={email}
            onChange={event => setEmail(event.target.value)}
            required
        />

        <button type="submit">
            Login
        </button>
    </form>
);

}

15. useRef

useRef stores a value between renders without causing a re-render when that value changes. It is commonly used for DOM references and values that are not needed to render the UI.

const inputRef = useRef(null);

function focusInput() {
    inputRef.current.focus();
}

return (
    <>
        <input ref={inputRef} />
        <button onClick={focusInput}>
            Focus input
        </button>
    </>
);

}

16. useEffect

useEffect synchronizes a component with external systems, such as browser APIs, subscriptions, timers, or third-party widgets. It is not necessary for every calculation or user interaction. 

import { useEffect } from "react";

useEffect(() => {
console.log("Effect started");

return () => {
    console.log("Effect cleaned up");
};

}, []);

Dependency array behavior:

// Runs after every committed render

useEffect(() => {
// ...
});

// Runs after the initial mount
// and when the component is mounted again
useEffect(() => {
// ...
}, []);

// Runs after the initial mount and when userId changes
useEffect(() => {
// ...
}, [userId]);

The cleanup function runs before the effect is re-executed with changed dependencies and when the component unmounts. In development Strict Mode, React may run an extra setup-and-cleanup cycle to help detect bugs.

17. Fetching Data from an API

The browser's fetch() API makes HTTP requests. When using it in an effect, handle loading, errors, and stale requests. 

import { useEffect, useState } from "react";

function Users() {
const [users, setUsers] = useState([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState("");

useEffect(() => {
    const controller = new AbortController();

    async function loadUsers() {
        try {
            setLoading(true);
            setError("");

            const response = await fetch(
                "https://jsonplaceholder.typicode.com/users",
                { signal: controller.signal }
            );

            if (!response.ok) {
                throw new Error("Failed to fetch users");
            }

            const data = await response.json();
            setUsers(data);
        } catch (err) {
            if (err.name !== "AbortError") {
                setError(err.message);
            }
        } finally {
            if (!controller.signal.aborted) {
                setLoading(false);
            }
        }
    }

    loadUsers();

    return () => controller.abort();
}, []);

if (loading) return <p>Loading...</p>;
if (error) return <p>Error: {error}</p>;

return (
    <ul>
        {users.map(user => (
            <li key={user.id}>{user.name}</li>
        ))}
    </ul>
);

}

For larger applications, consider a framework's data-loading features or a data-fetching library instead of implementing caching, retries, and request deduplication yourself.

19. useReducer

useReducer manages state using a reducer function. It can make complex state transitions easier to organize than multiple state setters. 

import { useReducer } from "react";

function reducer(state, action) {
switch (action.type) {
case "increment":
return { count: state.count + 1 };

    case "decrement":
        return { count: state.count - 1 };

    default:
        return state;
}

}

function Counter() {
const [state, dispatch] = useReducer(reducer, {
count: 0
});

return (
    <>
        <p>{state.count}</p>
        <button onClick={() => dispatch({ type: "increment" })}>
            +
        </button>
        <button onClick={() => dispatch({ type: "decrement" })}>
            -
        </button>
    </>
);

}

20. Custom Hooks

A custom Hook is a JavaScript function whose name starts with use and which can call other Hooks. It lets you reuse stateful logic between components. 

import { useState } from "react";

function useToggle(initialValue = false) {
const [value, setValue] = useState(initialValue);

function toggle() {
    setValue(previousValue => !previousValue);
}

return [value, toggle];

}

function App() {
const [isOpen, toggleOpen] = useToggle();

return (
    <button onClick={toggleOpen}>
        {isOpen ? "Close" : "Open"}
    </button>
);

}

21. Rules of Hooks

  • Call Hooks at the top level of a function component or custom Hook.
  • Do not call Hooks inside loops, conditions, or nested functions.
  • Do not call Hooks from ordinary JavaScript functions that are not components or custom Hooks.
  • Keep component rendering pure: do not modify external state or perform side effects during render.

22. React 19: Form Actions

React 19 supports function Actions for form submissions and transitions. Passing a function to a form's action prop allows React to handle submission and pending state. 

function SaveForm() {
async function saveData(formData) {
    const name = formData.get("name");

    // Send the data to your server here.
    console.log("Saving:", name);
}

return (
    <form action={saveData}>
        <input name="name" required />
        <button type="submit">Save</button>
    </form>
);

}

A real application should validate submitted data on the server and handle failures. A client-side Action does not make an operation secure by itself.

23. React 19: useActionState

useActionState manages the result of an Action and exposes a pending flag. It is useful for forms that need to display server responses. 

import { useActionState } from "react";

async function submitForm(previousState, formData) {
const name = formData.get("name");

if (!name) {
    return { message: "Name is required" };
}

// Replace with a real server request.
return { message: `Hello, ${name}!` };

}

function NameForm() {
const [state, formAction, isPending] = useActionState(
submitForm,
{ message: "" }
);

return (
    <form action={formAction}>
        <input name="name" required />

        <button disabled={isPending}>
            {isPending ? "Submitting..." : "Submit"}
        </button>

        <p>{state.message}</p>
    </form>
);

}

24. React 19: useOptimistic

useOptimistic lets an interface display an anticipated result while an Action is in progress. The final UI should still reflect the actual result from the operation. 

import { useOptimistic, useState, startTransition } from "react";

function LikeButton() {
const [liked, setLiked] = useState(false);

const [optimisticLiked, setOptimisticLiked] =
    useOptimistic(liked);

async function handleLike() {
    startTransition(async () => {
        setOptimisticLiked(!liked);

        // Replace with an actual server request.
        await Promise.resolve();

        setLiked(previousLiked => !previousLiked);
    });
}

return (
    <button onClick={handleLike}>
        {optimisticLiked ? "Liked" : "Like"}
    </button>
);

}

25. React 19: The use API

React's use() API can read a Promise or Context. Unlike Hooks such as useState, it can be called inside conditions and loops in supported situations. When a Promise is pending, it can work with Suspense; rejected Promises can be handled by an Error Boundary. 

import { Suspense, use } from "react";

function Message({ messagePromise }) {
const message = use(messagePromise);

return <p>{message}</p>;

}

function App({ messagePromise }) {
return (
Loading message...

);
}

Pass a stable Promise from an appropriate parent or data layer. Creating a new Promise on every render can cause repeated suspension.

26. Suspense

Suspense displays fallback content while a supported child suspends during rendering, such as when using certain lazy-loaded components or Suspense-enabled data sources.

function App() {
return (

);
}

Suspense does not automatically detect every data request made inside a normal useEffect.

29. Error Boundaries

An Error Boundary displays fallback UI when a descendant component throws an error during rendering or certain lifecycle operations. It does not automatically catch every error in event handlers or asynchronous callbacks. 

import { Component } from "react";

class ErrorBoundary extends Component {
constructor(props) {
super(props);
this.state = { hasError: false };
}

static getDerivedStateFromError() {
    return { hasError: true };
}

componentDidCatch(error, info) {
    console.error("UI error:", error, info);
}

render() {
    if (this.state.hasError) {
        return <h2>Something went wrong.</h2>;
    }

    return this.props.children;
}

}

export default ErrorBoundary;

Error Boundaries are commonly implemented using class components or libraries that provide boundary components.

32. React Best Practices

  • Prefer function components and Hooks for new components.
  • Keep components small and focused on clear responsibilities.
  • Keep rendering pure; perform side effects in event handlers or effects as appropriate.
  • Never mutate React state directly.
  • Use stable keys when rendering lists.
  • Use semantic HTML and accessible labels for form fields.
  • Keep secrets on the server, not in frontend code.
  • Handle loading, empty, and error states when fetching data.
  • Clean up subscriptions, timers, and requests when necessary.
  • Use a router when an application has multiple URL-based views.
  • Use memoization when it provides a measured benefit.
  • Use React DevTools to inspect components and investigate performance.

33. Quick Reference

  • useState — Manage component state.

  • useRef — Store a mutable value or reference a DOM node.
  • useContext — Read a context value.
  • useReducer — Manage state through a reducer.
  • useMemo — Cache a calculated value.
  • useCallback — Cache a function definition.
  • memo — Optimize rendering of a component when appropriate.
  • useActionState — Manage an Action's result and pending state.
  • useOptimistic — Display an optimistic state during an Action.
  • use — Read a Promise or Context in supported situations.
  • Suspense — Display fallback UI while supported content suspends.
  • lazy — Load a component dynamically.
  • createContext — Create a Context object.
  • createRoot — Mount a React application into the DOM.
  • createPortal — Render content into a different DOM node.
